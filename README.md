# 校园外卖

## 项目简介

本项目是面向高校师生打造的轻量化校园生活服务平台，采用前后端分离架构开发，聚焦校园内商品/餐食的线上浏览、下单、订单管理等核心场景，解决校园内线下消费效率低、信息不透明等问题，为师生提供便捷的线上消费体验，同时为商家提供标准化的商品、订单管理能力。

项目为个人独立开发完成，覆盖需求分析、数据库设计、后端接口开发、前后端联调、系统测试全流程。

## 技术架构

### 后端技术栈

- 核心框架：SpringBoot 2.7.3
- 持久层框架：MyBatis（XML 动态 SQL + 注解）
- 分页插件：PageHelper
- 数据库：MySQL 8.0
- 缓存中间件：Redis
- 消息队列：RabbitMQ（死信队列实现订单超时自动关闭）
- 权限认证：JWT（管理端/用户端双拦截器）
- 对象存储：MinIO（自建，兼容 S3 协议）
- 实时推送：WebSocket（管理端来单提醒/催单）
- 报表导出：Apache POI（Excel）
- AI 能力：DeepSeek 大模型（OpenAI 兼容协议，智能点餐推荐）
- 接口文档：knife4j
- 项目构建：Maven

### 前端技术栈

- 前端框架：Vue3
- UI组件库：Element Plus
- 网络请求：Axios

## 核心功能

### 管理端

1. **员工管理模块**：员工登录、增删改查、启禁用、修改密码
2. **分类管理模块**：菜品分类、套餐分类管理
3. **菜品管理模块**：菜品增删改查、口味维护、起售停售、图片上传
4. **套餐管理模块**：套餐增删改查、起售停售
5. **店铺管理模块**：店铺营业状态设置（Redis 缓存）
6. **订单管理模块**：订单条件搜索、接单/拒单/派送/完成/取消、各状态数量统计
7. **工作台模块**：今日营业额/有效订单/完成率/客单价/新增用户、菜品/套餐/订单概览
8. **数据统计模块**：营业额/用户/订单统计、销量 Top10、运营数据 Excel 导出

### 用户端

1. **微信登录**：小程序 code 换 openid，新用户自动注册，JWT 签发
2. **商品浏览**：菜品/套餐/分类查询（Redis 缓存热点数据）
3. **购物车**：添加、修改数量、查看、清空
4. **地址簿**：收货地址增删改查、默认地址
5. **下单**：订单主表+明细表快照写入、购物车清空
6. **订单支付**：支付网关抽象（默认模拟支付，契约对齐微信支付 V3，配置一键切换 mock/real）
7. **订单管理**：历史订单、订单详情、取消（已支付自动退款）、催单、再来一单
8. **AI 智能点餐推荐**：自然语言点餐（如"推荐50块以内不辣的双人餐"），大模型三步流水线：参数提取 → 结构化查库过滤 → 推荐方案生成，支持一键加入购物车，大模型不可用时自动降级为规则推荐

### 通用

1. **订单超时自动关闭**：下单后发延时消息，超时未支付自动取消（RabbitMQ 死信队列 + 条件更新幂等）
2. **公共字段自动填充**：AOP + 自定义注解，自动填充创建人/创建时间/修改人/修改时间
3. **全局异常处理**：统一异常拦截，业务异常/系统异常分类响应
4. **来单提醒**：支付成功后 WebSocket 向管理端实时推送（语音播报），催单同步推送

## 快速开始

### 环境要求

- JDK 8+（项目在 JDK 21 下验证运行）
- MySQL 8.0
- Redis（默认 127.0.0.1:6379，密码 123456）
- RabbitMQ（订单超时关单依赖）

### 步骤

1. 初始化数据库：执行 `sql/01-schema.sql`（全新环境）；已有数据库执行 `sql/02-ai-spicy-migration.sql` 升级
2. 可选：执行 `sql/03-demo-data.sql` 造演示数据（测试用户/历史订单）
3. 配置环境变量：
   - `MYSQL_PASSWORD`：数据库密码（必填）
   - `CAMPUS_AI_API_KEY`：DeepSeek API Key（可选，不配则 AI 推荐自动走规则降级）
4. 启动 Redis、RabbitMQ、MySQL，运行 `campus-server` 启动类
5. 接口文档：http://localhost:8080/doc.html

### 演示技巧

- **快速看延时关单**：把 `application-dev.yml` 里 `campus.order.pay-timeout-ms` 临时改成 `60000`（60秒），下单不支付，1分钟后订单自动取消
- **模拟支付回调**：把 `campus.pay.mock-auto-pay` 置为 `false`，调支付接口后再调 `POST /user/order/payment/mock-notify?orderNumber=xxx` 模拟微信回调

## 设计说明与已知改进点

- **支付**：个人开发者无微信支付商户资质，支付网关按微信支付 V3 接口契约实现模拟网关（`campus.pay.mode=mock`），真实实现已预留（委托微信 V3 jsapi 下单+退款），切换仅改配置
- **延时消息**：RabbitMQ 无原生延时消息，用「消息级 TTL + 死信交换机」实现，规避队列级 TTL 的队头阻塞问题；生产可改用延时插件或 RocketMQ 原生延时消息
- **订单幂等**：支付成功/超时关单/状态流转全部基于带条件的 UPDATE（影响行数判断），并发场景先到先得
- **缓存**：菜品缓存未设 TTL、无空值缓存防护，清理用 KEYS 命令——生产应改 SCAN + 合理 TTL（复盘清单项）
- **订单号**：使用时间戳生成，同一毫秒并发下单存在撞号理论可能，可改为时间戳+用户id尾号
- **WebSocket**：与打包前端协议对齐，握手未校验 JWT（仅广播订单号等低敏信息），生产化应在连接参数校验 token
